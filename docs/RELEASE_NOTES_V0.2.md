# V0.2 迭代说明与注意事项

发布日期：2026-10-09

## 本次完成

- 将工作台定位为“统一门户 + 应用注册中心”，登记四个业务方向：问题经验、项目管理、标准化优选件、质量决策助手；
- 内置应用改为幂等更新，已有本地数据库不会因曾经初始化过而漏掉新模块；
- 为独立系统增加可配置入口：`PROBLEM_HUB_URL`、`PM_PLATFORM_URL`；未配置时显示“待配置”，不跳到模拟页面；
- 移除在线 Google 字体依赖，支持无外网环境下的页面加载；
- 收紧应用创建接口：使用服务端字段校验、受限 ID 格式、草稿默认态；
- 修正首页状态文案，不再声称模型网关或外部数据总线已连接。

## 升级注意事项

1. 本地 SQLite 在启动时会为 `app_registry` 自动补充两个可空字段；这是兼容旧试点库的最小升级。生产 PostgreSQL 上线前应改为受版本控制的迁移脚本。
2. 应用注册不是权限系统。上线前须从已验证的子系统逐步抽取认证、RBAC、审计能力，切勿把门户的匿名试点接口直接暴露到生产网络。
3. 外部地址和密钥不写入仓库。复制 `.env.example` 后在部署环境填写入口；HTTPS、SSO、网络白名单与权限映射需另行验收。
4. `workbench/data/` 中包含本地试点数据和上传样本，不应作为生产数据源或提交到公开仓库。

## 二期建议顺序

1. 为 B/C 两个已有系统补齐安全基线、备份恢复与测试复核；
2. 从已验证的重复能力中抽取公共包，优先适配器、统一错误响应与审计；
3. 拿到 PLM/QMS/飞书契约与测试权限后，分别建设真实接入；
4. 收齐样本和规则后再启动标准化与质量决策的 AI 能力，模型接入须有评测、版本记录与人工审核。
