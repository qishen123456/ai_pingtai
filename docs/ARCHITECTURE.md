# AI 平台架构说明（V0.2）

更新日期：2026-10-09。本文描述当前已落地的门户边界，不把规划能力写成已实现能力。

## 定位

`workbench` 是统一门户与轻量试点，不是把所有业务代码揉成一个单体。它负责：

- 应用注册：统一登记模块名称、负责人、生命周期、部署入口和建设依据；
- 工作入口：问题经验导入试点在本应用中可运行，独立系统通过环境配置跳转；
- 可追溯展示：计划中模块明确显示为“规划中”，不展示虚假的数据或模型连通状态。

## 边界与分层

```text
浏览器
  └─ workbench：门户、应用注册、问题经验导入试点
       ├─ problem-hub：问题经验企业版（独立部署）
       ├─ pm-platform：项目管理系统（独立部署）
       ├─ 标准化与优选件：待建设
       └─ 质量决策助手：待建设

公共能力（按实际消费者逐步抽取）：认证/RBAC、审计、适配器、规则、评测、备份
数据与集成：PLM、QMS、飞书等，只能通过受控适配器接入
```

## 迭代原则

1. 不改动已独立运行的子系统来“合并代码”；公共能力先双跑验证，再逐项迁移。
2. 外部接口未明确时只做接口契约和模拟标记，不能伪造地址或把演示数据当生产数据。
3. 规则、权限、关键计算使用确定性代码；AI 只做受控的理解、检索与生成，并保留证据和人工审核。
4. 密钥、账号和服务地址都只来自环境变量。`PROBLEM_HUB_URL`、`PM_PLATFORM_URL` 未设置时，门户不提供假链接。

## 当前可运行范围

- `GET /api/health`：门户健康检查；
- `GET/POST /api/apps`：应用注册表（新增应用默认草稿）；
- 问题经验 Excel 导入、预览、确认入库：现有试点能力；
- 其他模块：仅显示已知建设状态，需在各自仓库独立验证与部署。
